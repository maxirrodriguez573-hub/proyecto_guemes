SQL:

TABLA GASTO
- gasto_id -> PK / AI
- telegram_usuario_id -> NOT NULL, INT
- categoria_id (FK) -> NOT NULL, INT, FK (CATEGORIA.categoria_id)
- comercio_id (FK) -> NOT NULL, INT, FK (COMERCIO.comercio_id)
- fecha -> NOT NULL, TEXT 
- monto -> NOT NULL, REAL 
- descripcion NULLEABLE, TEXT
- recibo_file_id NOT NULL, TEXT

TABLA CATEGORIA (Ferretería, librería, supermecado, limpieza)
- categoria_id PK / AI
- nombre NOT NULL, TEXT, UNIQUE

TABLA COMERCIO (112, el enano, Lore, Carrefour)
- comercio_id PK / AI 
- nombre NOT NULL, TEXT, UNIQUE
- dirección NULLEABLE, TEXT (FUTURO) 
- horario NULLEABLE, TEXT(FUTURO)



FUNCIONES DE LAS TABLAS 

TABLA CATEGORIA 
Esta tabla debe tener datos fijos y el usuario no tendría que añadir los datos pero está la opción.

- AGREGAR CATEGORIA ( nombre ) x
- ELIMINAR CATEGORIA x
- OBTENER UNA CATEGORIA x
- OBTENER LA LISTA DE CATEGORIAS x

TABLA COMERCIO 
Esta tabla tiene que tener los datos principales del comercio para que después se puedan comparar entre sí. 
El usuario debería gestionar esta tabla.

- AGREGAR COMERCIO ( nombre, dirección (opcional), horario (opcional) ) x
- ELIMINAR COMERCIO x
- OBTENER UN COMERCIO x
- OBTENER LA LISTA DE LOS COMERCIOS x

- MODIFICAR NOMBRE DEL COMERCIO
- MODIFICAR DIRECCIÓN DEL COMERCIO
- MODIFICAR HORARIO DEL COMERCIO 


TABLA GASTO
Tabla principal donde el usuario lo usará siempre y con datos obligatorios.

- AGREGAR GASTO ( tel_usuario_id , cat_id, comer_id, fecha (por defecto fecha actual), monto, descr., recibo_id )
- ELIMINAR GASTO 
- OBTENER UN GASTO
- OBTENER LA LISTA DE GASTOS

- MODIFICAR UN GASTO 


VALIDACIONES 
- FUNCIONES DE ELIMINACIÓN y MODIFICACIÓN utilizar .rowcount para verificar si la eliminación fue correcta
- FUNCIONES DE OBTENER  utilizar fetchone/fetchall para verificar si hay registros
- FUNCIONES DE AGREGACIÓN utilizar .lastrowid para verificar el id del registro
